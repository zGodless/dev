# TCP
    精髓：开放性和实用性
    
    有连接（区别于UDP的无连接）
 ## TCP与UDP
    没有绝对的优劣，TCP有连接，提供传输可靠性，但是时效性没有那么高，UDP虽然不提供可靠性，但在时效性要求高的应用，比如语音/视频通话（偶发丢失消息可以接受）中优于TCP

 ## RFC规范（Request for comment）

 ## 数据包结构
    层层打包：TCP数据包 + TCP包首部 + IP包首部 + 以太网包首部
 
 ## 通过序列号与确认应答（ACK）提高可靠性
    将通信数据分段标识序列号，发送方告诉接收方“我发送到哪一个节点了”，而接收方应答的时候告诉发送方“我接收到哪一个节点了”（ACK确认号），这样避免重发，而发送方连续收到同一个序列号的ACK则会将其所对应的数据进行重发，确保不会丢包（该重发机制比超时重发更快）。
 ## 超时重发机制
    每次发包都会计算往返时间及其偏差，二者相加，重发超时的时间就是比这个总和稍微大一点，后续若是还收不到确认应答，则等待时间以2倍、4倍的指数函数增长，到一定重发次数后，则会认为发生异常，强行关闭连接。
 ## 连接机制（三次握手）
    客户端发送SYN请求连接 --> 服务端ACK确认应答，同时发送SYN请求建立连接 --> 客户端ACK确认应答，建立连接。
 ## 最大消息长度（MSS: Maximum Segment Size）
    三次握手的时候两端主机各自在TCP首部中写入MSS选项，告诉对方自己能适应的MSS大小，然后在两者中选一个较小的投入使用。
 ## 滑动窗口控制
    TCP并不是一段一段发送，一个一个等待应答，那样太慢，性能低。
    引入“窗口”概念：无需等待确认可以继续发送的数据的最大值。使用缓冲区把待确认的数据缓存，以实现丢包等无应答场景下的重传（连续3次收到重复的确认应答时进行重发）。
    实际上，大可不必每一个数据段都进行ACK确认应答，因为滑动窗口控制机制，通常应答少一点也无妨，TCP文件传输中，大多数是每两个数据段返回一次ACK，以提高网络利用率。
 ## 流控制
    TCP首部中有一个字段用来通知窗口大小，接收主机将自己的缓冲区大小放入这个字段通知发送方，这个字段的值越大，说明网络吞吐量越高。也就是说发送端主机会根据接收端主机的指示，对发送数据进行流量控制。
    发送端时不时会发送窗口探测包来确认这个大小。
 ## 拥塞控制（慢启动）
    为了避免突然发送大量数据导致网络拥堵，TCP在通信刚开始会通过慢启动算法对发送数据量进行控制。
    拥塞窗口：慢启动的时候设置为1个数据段（1MSS），每次收到ACK，拥塞窗口增加1，再发送时比较拥塞窗口和接收端主机通知的窗口（缓冲区大小），取较小的值，发送比其小的数据量。
    慢启动有阈值，超过这个值的时候，拥塞窗口的增大会减缓。
    于是当TCP通信开始后，网络吞吐量会逐渐上升，随着网络拥堵的发生，吞吐量会急速下降，然后再次进入吞吐量慢慢上升的过程。

# IP
    IP面向无连接，所以并非可靠（丢包等问题），而TCP协议面向有连接，提供了可靠性

 ## IP地址的分类
    A类：“0”开头，1~8位为网络标识，后面24位为主机标识，例如0.0.0.0 ~ 127.0.0.0
    B类：“10”开头，1~16位为网络标识，后面16位为主机标识，例如128.0.0.0 ~ 191.255.0.0
    C类：“110”开头，1~24位为网络标识，后8位为主机标识，例如192.0.0.0 ~ 223.255.255.0，一个网段可容纳上限为254个
    D类：“1110”开头，全部32位为网络标识，没有主机标识，用于多播

 ## IP广播
    一个IP地址的主机地址全部设置为二进制的1，就成了广播地址，比如 10101100.00010100.00000000.00000000，改为10101100.00010100.11111111.11111111，即172.20.255.255，
    就成了广播地址，这个IP会被路由器屏蔽，因此不会到达172.20网段以外的链路上，可以对172.20网段上的所有主机进行广播
 
 ## IP多播
    采用D类IP地址，前4位为“1110”，范围是224.0.0.0 ~ 239.255.255.255

 ## 子网掩码
    作用：避免IP地址分配范围太大造成的浪费，比如：架构B类IP网络的时候，理论上同一链路可以连接6万5千多台主机，显然不现实，子网掩码可以“掩盖”掉一部分IP地址不被使用
    子网掩码可以自由规定一个IP地址的网络标识占用位数、主机标识占用位数，规则是：将网络标识部分的位全部设为“1”，而主机标识部分的位全部设为“0”
    举例：将192.168.0.1的前26位为网络标识，后6位为主机标识，则子网掩码可以设置为 11111111.11111111.11111111.11000000，即 255.255.255.192，（也可写成192.168.0.1/26 或 192.168/26）
          **同时，对应的广播地址为192.168.0.63
  ### CIDR（Classless Inter-Domain Routing 无类型域间选路）
    使用子网掩码来限制IP地址的区块分配
  ### VLSM（Variable Length Subnet Mask 可变长子网掩码）
    使组织内部各部门的子网掩码可自由修改

 ## 公网IP和私有IP
    一般形式：路由器上设置公网IP，个人主机设置私有IP，个人主机需要联网的时候通过NAT进行通信

 ## IP分割处理与再构成（MTU）
    数据包超过链路上限限制时，路由器会将IP数据进行分片，这个最大传输单元（MTU）在各个链路上不同，IP的限制最宽，为65535（因为IP包首部表示总数据长度的字段占用了16个比特位，最大只能表示65535），最后在目的地主机上进行重组
  ### 路径MTU发现
    即提前发现整条路径上的最小MTU限制，一次分割到位(主机来分割，不在路由器上做)，防止多次分割

 ## IPv6
   地址长度为128 bit，每16比特为一组，用冒号（:）分隔，出现连续的0时还可以省略，用两个冒号（::）分隔，但一个地址中只允许出现一次双冒号
  ### 地址组成
    前64位为网络标识，后64位为主机标识
  ### 分片
    由主机进行分片，路由器不负责，因此IPv6中的“路径MTU发现”功能必不可少，这是为了减少路由器负担，提高网速

 ## DNS域名解析（Domain Name System）
    类似互联网中的分布式数据库

 ## DHCP(Dynamic Host Configuration Protocol)动态IP分配协议
    很多时候由路由器充当DHCP服务器的角色

 ## NAT(Network Address Translator) 
    是用于在本地网络中使用私有地址，在连接互联网时转而使用全局IP地址的技术。
    穿透内网
 ## IP隧道
    在IPv4首部外套一个IPv6的首部，用来穿过无法处理IPv4的IPv6节点，或者反过来在IPv6外面包一层IPv4首部

 ## 端口号
    TCP/IP或UDP/IP使用“5个信息”来区分是否同一个通信，即：协议号、源IP地址、源端口、目标IP地址、目标端口。任意一个不同即视作不同的通信，因此TCP通信和UDP通信可以使用同一个端口号
    HTTP通信只支持TCP协议


# UDP（User Datagram Protocol）
    不提供复杂的控制机制，利用IP提供面向无连接的通信服务。
    不处理丢包、乱序、重发等问题。
    适用场景：1、包总量较少的通信（DNS、SNMP等）
             2、视频、音频等多媒体通信（即时通信）
             3、限定于LAN等特定网络中的应用通信
             4、广播通信（广播、多播）
