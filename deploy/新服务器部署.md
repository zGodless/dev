# C137 新服务器部署手册

本文记录在 Ubuntu 24.04 虚拟机上完整跑通的部署流程。该演练环境没有域名、SSL 证书和 CDN，使用 `http-rehearsal` 内网模式。

## 1. 部署形态

```text
Rick gRPC
  -> http://<服务器IP>:8081
  -> Portal HTTP/2

Rick 媒体 WebSocket / Morty WebSocket
  -> ws://<服务器IP>:8080
  -> Portal HTTP/1.1 WebSocket
```

内网模式不启动 Nginx，不暴露 80/443，仅绑定：

```text
<服务器IP>:8080
<服务器IP>:8081
```

只能用于受控内网演练，不能作为公网生产入口。

## 3. 本地构建部署包

在 Windows 构建机执行：

```powershell
cd E:\zyl\code\C137

dotnet restore src\Portal\Portal.csproj -m:1 /nr:false

dotnet publish src\Portal\Portal.csproj `
  -c Release `
  --self-contained false `
  --no-restore `
  -o artifacts\portal-linux-x64 `
  -m:1 /nr:false

dotnet ef migrations script `
  --configuration Release `
  --no-build `
  --context PortalDbContext `
  --project src\Portal\Portal.csproj `
  --startup-project src\Portal\Portal.csproj `
  --output artifacts\portal-migrations.sql
```

打包：

```powershell
tar -czf .\artifacts\c137-new-server.tar.gz `
  artifacts/portal-linux-x64 `
  deploy/docker `
  deploy/ubuntu `
  deploy/autoshell `
  deploy/database `
  artifacts/portal-migrations.sql

Get-FileHash .\artifacts\c137-new-server.tar.gz -Algorithm SHA256
```

内网客户端必须在打包前将 `src/Shared/Configuration/DeploymentEndpoints.json` 的 Release 端点改为：

```json
"MortyPortalWebSocketUri": "ws://<服务器IP>:8080/ws/morty",
"RickPortalAddress": "http://<服务器IP>:8081",
"RickPortalWebSocketUri": "ws://<服务器IP>:8080"
```

生产 CDN 模式使用：

```json
"MortyPortalWebSocketUri": "wss://<域名>/ws/morty",
"RickPortalAddress": "https://<域名>",
"RickPortalWebSocketUri": "wss://<域名>"
```

## 4. 上传与解压

本地执行：

```powershell
scp .\artifacts\c137-new-server.tar.gz <ssh-user>@<服务器IP>:/tmp/c137-new-server.tar.gz
```

服务器执行：

```bash
sha256sum /tmp/c137-new-server.tar.gz

sudo install -d -o root -g root -m 0755 /opt/c137/build
sudo tar -xzf /tmp/c137-new-server.tar.gz -C /opt/c137/build
```

确认插件数量：

```bash
find /opt/c137/build/artifacts/portal-linux-x64/Plugins \
  -maxdepth 1 -type f -name '*.dll' | wc -l
```

```text
10
```

## 5. 初始化 Ubuntu 与 Docker

默认使用 Docker 官方源：

```bash
cd /opt/c137/build
sudo bash ./deploy/ubuntu/install-docker.sh
```

如果 Docker 官方源 TLS 超时，使用阿里云 Docker CE 镜像源：

```bash
sudo env C137_DOCKER_APT_MIRROR=aliyun \
  bash ./deploy/ubuntu/install-docker.sh
```

sudo docker compose version
sudo docker info --format 'Server={{.ServerVersion}} StorageDriver={{.Driver}}'

## 15. 本次发现并修复的问题

### 15.1 日志文件创建竞态

现象：

```text
chmod: cannot access '<log-file>': No such file or directory
```

原因是 `tee` 尚未创建文件时，脚本已经执行 `chmod`。修复为：

```bash
touch "$log_file"
chmod 0600 "$log_file"
exec > >(tee "$log_file") 2>&1
```

### 15.2 部署包脚本无 executable bit

现象：

```text
production-config-verify.sh: Permission denied
```

修复为执行脚本内部显式调用：

```bash
bash "$SCRIPT_DIR/xxx.sh"
```

不再依赖部署包中脚本的可执行位。

### 15.3 备份脚本月份目录变量残留

现象：

```text
AVATAR_DIR: unbound variable
```

修复为：

```bash
-v "$avatar_dir":/backup
```

### 15.4 数据库初始化脚本相对路径错误

现象：

```text
cd: ./deploy/autoshell: No such file or directory
```

原因是脚本先进入 Compose 目录，再用相对的 `${BASH_SOURCE[0]}` 计算脚本路径。修复为脚本启动时先计算绝对 `SCRIPT_DIR`。

### 15.5 Docker 官方源在内网 VM 上不稳定

现象：

```text
Could not handshake: Error in the pull function
```

修复为支持：

```bash
C137_DOCKER_APT_MIRROR=aliyun
```

并保留默认 `official` 模式。
