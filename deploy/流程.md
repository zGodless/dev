## 构建发布/部署包
### 1、构建 Portal 发布目录
执行位置：
```
E:\zyl\code\C137
```
命令：
``` powershell
dotnet publish src\Portal\Portal.csproj `
  -c Release `
  --self-contained false `
  --no-restore `
  -o artifacts\portal-linux-x64 `
  -m:1 /nr:false
```
说明：
- -c Release：使用 Release 配置；
- --self-contained false：使用框架依赖部署，运行时由 Docker 基础镜像提供；
- -o artifacts\portal-linux-x64：输出到部署目录；
- -m:1 /nr:false：禁用并行 MSBuild 节点，符合项目构建约束；
- 不使用 -r linux-x64，因为 Portal 会连带触发多个 .NET Framework 4.6.2 插件项目构建，指定 Linux RID 会导致这些 net462 插件项目的 assets 文件不匹配。

Portal 是框架依赖模式，Linux 运行时由这个镜像提供：
```
FROM mcr.microsoft.com/dotnet/aspnet:10.0
```
### 2、生成数据库迁移脚本
命令：
```powershell
dotnet ef migrations script `
  --idempotent `
  --configuration Release `
  --no-build `
  --context PortalDbContext `
  --project src\Portal\Portal.csproj `
  --startup-project src\Portal\Portal.csproj `
  --output artifacts\portal-migrations.sql
```
生成：
```
E:\zyl\code\C137\artifacts\portal-migrations.sql
```
--idempotent 表示脚本是幂等迁移脚本，可重复执行，MySQL 会根据 __EFMigrationsHistory 判断哪些迁移已经应用。

### 3、打包命令
在仓库根目录执行：
```powershell
tar -czf artifacts/c137-deploy-bundle.tar.gz `
  artifacts/portal-linux-x64 `
  deploy/docker `
  deploy/database `
  artifacts/portal-migrations.sql
```
校验包命令：
```powershell
Get-FileHash `
  E:\zyl\code\C137\artifacts\c137-deploy-bundle.tar.gz `
  -Algorithm SHA256
```
### 4、在虚拟机上如何使用这个包
上传后在 Ubuntu 上：
```bash
sudo mkdir -p /opt/c137/build
sudo tar -xzf /tmp/c137-deploy-bundle.tar.gz -C /opt/c137/build
cd /opt/c137/build

sudo docker build \
  -f deploy/docker/Portal.Dockerfile \
  -t c137-portal:local .
```
Portal.Dockerfile 里的关键行是：
```dockerfile
COPY artifacts/portal-linux-x64/ .
```
所以包里的 artifacts/portal-linux-x64 是构建 Docker 镜像的必需输入。

### 2、 确认 /etc/c137 下的运行时文件
需要存在：
```
/etc/c137/portal-env
/etc/c137/mysql-root-password
/etc/c137/mysql-portal-password
/etc/c137/certs/<你的测试域名>/fullchain.pem
/etc/c137/certs/<你的测试域名>/privkey.pem
```
检查 portal-env 中的域名：

```bash
sudo grep '^export AllowedHosts=' /etc/c137/portal-env
```
应输出：
```bash
export AllowedHosts=<你的测试域名>
```
检查首次管理员密码是否已配置，但不显示密码：
```bash
if sudo grep -q '^export C137_BOOTSTRAP_ADMIN_PASSWORD=' /etc/c137/portal-env; then
    echo "Bootstrap admin 已配置"
else
    echo "Bootstrap admin 未配置"
fi
```
如果是首次初始化数据库，应该显示已配置。
检查证书：
```bash
sudo openssl x509 \
  -in "/etc/c137/certs/$DOMAIN/fullchain.pem" \
  -noout \
  -subject \
  -issuer \
  -dates \
  -ext subjectAltName
```
确认证书 SAN 包含你的测试域名。

### 3、 创建 .env
在 Compose 目录执行：

```bash
sudo docker compose config --quiet
```

没有输出就表示配置解析正常。

#### 重新执行 IAM / 权限 / 菜单基线脚本
执行下面整段：
```bash
cat > /tmp/init-c137-baseline.sh <<'SCRIPT'
#!/usr/bin/env bash
set -Eeuo pipefail

BUILD_ROOT=/opt/c137/build
COMPOSE_DIR="$BUILD_ROOT/deploy/docker"
DATABASE_DIR="$BUILD_ROOT/deploy/database"

cd "$COMPOSE_DIR"

apply_sql() {
    local file="$1"
    echo "Applying: $file"
    sudo docker compose exec -T mysql sh -c \
      'mysql --default-character-set=utf8mb4 -uroot -p"$(cat /run/secrets/mysql-root-password)" c137' \
      < "$file"
}

MIGRATION_COUNT="$(
    sudo docker compose exec -T mysql sh -c \
      'mysql -N -B -uroot -p"$(cat /run/secrets/mysql-root-password)" -e "SELECT COUNT(*) FROM c137.__EFMigrationsHistory;"'
)"

if [[ "$MIGRATION_COUNT" != "10" ]]; then
    echo "EF migration 数量不是 10，当前值：$MIGRATION_COUNT"
    echo "请先检查 portal-migrations.sql 是否完整执行。"
    exit 2
fi

echo "EF migration count: $MIGRATION_COUNT"

while IFS= read -r -d '' file; do
    base="$(basename "$file")"

    case "$base" in
        # 这些结构变更已经包含在完整 EF migration 中，
        # 重复执行会重复写迁移历史或操作已改名的表。
        002_*)
            echo "Skip EF-managed script: $file"
            continue
            ;;
        003_*)
            echo "Skip EF-managed script: $file"
            continue
            ;;
        014_audit_logs.sql)
            echo "Skip EF-managed script: $file"
            continue
            ;;
    esac

    apply_sql "$file"
done < <(
    find "$DATABASE_DIR" \
      -maxdepth 1 \
      -type f \
      -name '[0-9][0-9][0-9]_*.sql' \
      -print0 | sort -z
)

echo "C137 baseline scripts applied."
SCRIPT

bash /tmp/init-c137-baseline.sh
```
这个脚本会：
- 执行 001
- 跳过 002
- 跳过 003
- 执行 004 到 024
- 跳过 014_audit_logs.sql
- 执行 014_dynamic_module_navigation.sql
这是当前“完整 EF migration + 手工基线数据”的正确顺序。

#### 验证数据库基线是否成功
执行：
```bash
sudo docker compose exec -T mysql sh -c \
  'mysql -N -B -uroot -p"$(cat /run/secrets/mysql-root-password)" -e "
SELECT COUNT(*) AS migrations FROM c137.__EFMigrationsHistory;
SELECT COUNT(*) AS modules FROM c137.iam_modules;
SELECT COUNT(*) AS roles FROM c137.iam_roles;
SELECT COUNT(*) AS permissions FROM c137.iam_permissions;
SELECT COUNT(*) AS ui_resources FROM c137.iam_ui_resources;
"'
```
预期重点：
```
migrations = 10
modules = 7 左右
roles >= 6
permissions > 50
ui_resources > 20
```
再检查关键权限：
```bash
sudo docker compose exec -T mysql sh -c \
  'mysql -N -B -uroot -p"$(cat /run/secrets/mysql-root-password)" -e "
SELECT code FROM c137.iam_permissions
WHERE code IN (
  \"iam.scope.update\",
  \"plugin.uac_bypass.use\",
  \"plugin.info_collect.use\",
  \"plugin.hvnc.use\",
  \"socks5_proxy.management.view\"
)
ORDER BY code;
"'
```
预期 5 行都能查出来。
